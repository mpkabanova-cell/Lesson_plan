# Методические блоки этапов (конструктор v3)

Конструктор v3 (`/api/construct/start` → `stage` → `finish`) генерирует каждый этап как **полноценный методический сценарный блок**, а не как набор шаблонных заданий.

## Структура этапа

```markdown
## {название этапа}
Время: N мин
Цель: …
Методический приём: …
Речь учителя: «готовая речь с вопросами и инструкциями»
Предполагаемые ответы учеников:
- вариант 1
- вариант 2
- типичное затруднение
Ученики: …
Задание N.M: …
Ответ: …
Ожидаемый результат: …
Методический комментарий: …
```

Все 8 полей обязательны. Речь учителя — в кавычках `«…»`, не шаблон «организует обсуждение».

## Методические приёмы

Каталог: [`src/lib/constructor/data/stageTechniques.json`](../src/lib/constructor/data/stageTechniques.json).

Перед генерацией этапа `pickTechniqueForStage` выбирает приём по `stageId` (фаза FGOS), ротируя по индексу этапа и теме. Уже использованные приёмы в сессии исключаются.

Примеры по фазам:

| Фаза | Приёмы |
|------|--------|
| Мотивация | Удивляй, Отсроченная отгадка, Корзина идей, Проблемный вопрос |
| Актуализация | Верные/неверные утверждения, Блиц-опрос, Работа с ошибкой, Кластер |
| Затруднение | Проблемная ситуация, Противоречие, Пробное действие |
| Открытие | Подводящий диалог, Исследование, Анализ примеров, Работа с источником |
| Закрепление | Тренировочные задания, Взаимопроверка, Творческое применение |
| Рефлексия | Светофор, Синквейн, Рюкзак, ПОПС |

Рефлексия генерируется через LLM (не шаблон).

## Логика этапов

Дополнительные правила в [`stageContentRules.ts`](../src/lib/constructor/stageContentRules.ts):

- **Проблемная ситуация** — затруднение, без готового правила и эталонного решения новой темы
- **Актуализация** — пробное действие + затруднение, без объяснения нового
- **Открытие нового знания** — эталон, правило, алгоритм
- **Закрепление** — применение открытого способа, без нового материала
- **Рефлексия** — итог и самооценка, без новых заданий на усвоение

## Антидублирование заданий

[`stageTaskDiversity.ts`](../src/lib/constructor/stageTaskDiversity.ts) сравнивает условия заданий с предыдущими этапами (Jaccard ≥ 0.55). При повторе — код `duplicate_task` и повторная генерация (до 3 попыток).

## Валидация

[`stageValidators.ts`](../src/lib/constructor/stageValidators.ts) — `parseStageBlock`, проверка полей, речи, ответов учеников, приёма, предметного содержания, дублей.

Организационный момент — единственный шаблонный этап (`templateOnly`), с той же структурой блока.

## Отладка

При неуспешной валидации в следующий запрос LLM передаётся `fixInstructions` с перечнем ошибок.
